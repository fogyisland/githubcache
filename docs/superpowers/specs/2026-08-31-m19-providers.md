# M19 — Providers (JSON-Driven Ingestion Sources)

> **Status:** Draft, awaiting user review.

**Goal:** Add a new admin concept "ingestion provider" so operators can declaratively configure JSON-driven data sources whose contents are parsed into GitHub `owner/name` pairs and queued for refresh into the cache — end-to-end testable even when the GitHub token pool is empty.

**Architecture:** New DB table `ingestion_providers` (slug, kind='json', JSONPath-based config, enabled). Admin UI at `/admin/providers` for CRUD; ingestion page gets a new card "Run via provider" that calls `POST /api/admin/providers/[id]/preview` (parse + dedupe + report) and `POST /api/admin/providers/[id]/run` (enqueue refresh jobs). Parsing/extraction/dedupe live in `src/lib/ingestion/providers/`.

**Tech Stack:** Next.js 14 app router (RSC) + Prisma 5 (MySQL 5.7) + Zod 4 + next-intl 4 + Vitest 4.

**Spec:** This document is the spec. Implementation plan will derive from it.

---

## Global Constraints

- Next.js 14 app router; admin pages are server components unless explicitly marked `'use client'`.
- All admin routes use `cookiesFromRequest` from `@/lib/auth/cookies` (never `cookies()` from `next/headers`).
- Server-component tests must `await Component(...)` directly, never `createElement(AsyncComponent, ...)` (see [[feedback_async_server_component_tests]]).
- `exactOptionalPropertyTypes` is on — never pass `undefined`; use spread idiom `...(cond ? { x: y } : {})`.
- MySQL 5.7.44 (JSON_EXTRACT available).
- next-intl 4 strict namespaces — keys used under `admin.providers.*` must be declared under the `admin.providers` leaf.
- All `POST` admin routes are CSRF-guarded + audit-logged.
- Vitest 4 / oxc JSX: `vitest.config.ts` has `oxc: { jsx: 'automatic' }` set globally; no per-test config needed.
- No Docker (see [[feedback_no_docker]]).
- All memory: `metadata` JSON column sort/filter uses `JSON_UNQUOTE(JSON_EXTRACT(metadata, '$.field'))` (established in M18).
- `Prisma.raw` is a value, not a type — `import { Prisma } from '@prisma/client'`, never `import type`.

## Data Model

### Table: `ingestion_providers`

| Column          | Type                | Notes                                                       |
|-----------------|---------------------|-------------------------------------------------------------|
| `id`            | BIGINT PK AUTO_INC  |                                                             |
| `slug`          | VARCHAR(64) UNIQUE  | URL-safe; immutable after creation.                         |
| `name`          | VARCHAR(128)        | Display name; editable.                                     |
| `source_type`   | VARCHAR(32)         | Always `'json'` in M19. Reserving the column for future expansion (e.g. `'csv'`, `'http_api'`). |
| `config_json`   | JSON                | Source config (see schema below).                            |
| `enabled`       | BOOLEAN             | Soft-disable without delete.                                |
| `created_at`    | DATETIME(3)         |                                                             |
| `updated_at`    | DATETIME(3)         |                                                             |

Index: UNIQUE(`slug`).

### `config_json` schema (Zod)

```ts
const ProviderConfigSchema = z.discriminatedUnion('kind', [
  z.object({
    kind: z.literal('file'),
    path: z.string().min(1),       // absolute path on server filesystem
    itemsPath: z.string().min(1),  // JSONPath to array, e.g. '$.custom_nodes'
    urlField: z.string().min(1),   // field within each item containing a GitHub URL, e.g. 'files[0]'
  }),
  z.object({
    kind: z.literal('http'),
    url: z.string().url(),
    itemsPath: z.string().min(1),
    urlField: z.string().min(1),
    headers: z.record(z.string(), z.string()).optional(),
  }),
]);
```

Validation: config_json is validated against `ProviderConfigSchema` on create/edit; invalid configs are rejected at the API boundary.

## Backend Modules (under `src/lib/ingestion/providers/`)

### `extract.ts`

Pure utility. `parseGitHubUrl(input: string): { owner: string; name: string } | null`. Handles:
- `https://github.com/owner/name`
- `https://github.com/owner/name.git`
- `git@github.com:owner/name.git`
- `github.com/owner/name` (no scheme)
- Returns `null` for non-GitHub URLs and invalid inputs.

### `source.ts`

`loadProviderSource(config: ProviderConfig): Promise<unknown[]>`:
- `kind=file`: `fs.readFile(path, 'utf8')` + `JSON.parse`. Reject if path is outside project root (security: don't read arbitrary user-controlled paths via the API without an allowlist) — for M19 we use a server-side allowlist of paths checked into `.env` as `PROVIDER_FILE_ROOTS` (comma-separated absolute dirs); paths must be under one of them.
- `kind=http`: GET URL with optional headers, parse JSON. 30s timeout. Reject non-2xx.

After fetch, apply `itemsPath` via a minimal JSONPath subset:
- Support only `$.foo.bar[0]` and `$.foo[*].bar` style — no filter expressions, no recursive descent, no script expressions.
- Implement a tiny evaluator (~30 lines) sufficient for the documented examples; reject other patterns at config validation time.

For each item, read the field at `urlField` (must be a string — either a plain string or `array[index]` access; if it's an array and the field path ends with no index, take the first element).

### `run.ts`

`previewProvider(slug, opts?: { limit?: number }): Promise<PreviewResult>`:
1. Load provider by slug (404 if not found; 409 if disabled).
2. Call `loadProviderSource`.
3. For each item, extract URL via `urlField`, call `parseGitHubUrl`, skip `null`s.
4. Dedupe by `owner/name`.
6. Compare against `repositories` table:
   - `existing`: row exists with `fetch_status='ok'`
   - `stale`: row exists but `fetch_status` not 'ok' or `last_fetched_at` is null
   - `new`: no row
5. Return:
   ```ts
   { totals: { items, urls, unique, invalid, existing, stale, new },
     sample: { owner, name }[]   // up to 20 new owner/name }
   ```

`runProvider(slug, opts?: { limit?: number, dryRun?: boolean }): Promise<RunResult>`:
1. Same as preview up to step 4.
2. If `dryRun=true` (admin only, default false): return preview-shape counts without writing.
3. Otherwise: for each `new`/`stale` owner/name, INSERT into `refresh_jobs` with `reason='ingestion_provider:<slug>'`. Use the existing refresh scheduler path (no new scheduler).
4. Audit-log the run with `details: { slug, totals, dryRun, jobCount }`.
5. Return `{ totals, jobCount, dryRun }`.

### Pool-empty behavior

If `getPoolSize() === 0`, the run still creates refresh_jobs but each job will fail at fetch with `no_token_available`. The UI displays a yellow warning before submission:

> "GitHub token pool is empty — jobs will be enqueued but fail at fetch time. Configure a token in /admin/github-tokens to actually ingest."

## Admin UI

### Sidebar

New entry: `{ slug: 'providers', icon: '↥', href: '/admin/providers', roles: ['admin', 'operator'] }` — between `ingestion` and `audit`.

### `/admin/providers` (list)

RSC. Columns: slug, name, kind, enabled (toggle via POST form), last run (latest audit row), created.
Actions: New, Edit, Delete (admin only). Operator sees the list and can preview/run existing providers but cannot create/edit/delete.

### `/admin/providers/new` + `/admin/providers/[id]` (form)

RSC + small client island for JSON validation preview. Fields:
- name (text)
- slug (text, immutable after create; lowercase + hyphens)
- kind (radio: file / http)
- path (file only, conditional)
- url (http only, conditional)
- headers (http only, optional key-value list)
- itemsPath (text, e.g. `$.custom_nodes`)
- urlField (text, e.g. `files[0]`)
- enabled (checkbox, default true)
- "Test parse" button (admin only): calls `previewProvider` server-side, returns counts; renders inline. Catches invalid JSONPath, missing file, bad URL.

### `/admin/ingestion` extension

Below the existing recent-jobs table, add a new card "Run via provider":
- Provider dropdown (only `enabled=true` rows)
- "Preview" button (calls `/api/admin/providers/[id]/preview`)
- Result panel: total items / unique URLs / existing / stale / new / invalid counts + sample list
- "Run N jobs" button (disabled if new=0); submits to `/api/admin/providers/[id]/run`
- Yellow warning if pool empty.

### i18n

`admin.providers.*` namespace added under both `messages/zh.json` and `messages/en.json`:
- `title`, `description`, `breadcrumb`, `new`, `edit`
- `form.{name, slug, kind, path, url, headers, itemsPath, urlField, enabled}`
- `actions.{create, save, delete, toggle, testParse, runPreview, run}`
- `kind.{file, http}`
- `messages.{created, updated, deleted, enabled, disabled, parseOk, parseFailed, poolEmpty}`
- `run.{preview, run, totals, sample}`
- `sidebar.sections.providers`

## API Routes (all admin+operator, CSRF-guarded, audit-logged)

| Method | Path | Purpose |
|--------|------|---------|
| GET    | `/api/admin/providers` | List (paginated) |
| POST   | `/api/admin/providers` | Create (admin only) |
| GET    | `/api/admin/providers/[id]` | Get one |
| PATCH  | `/api/admin/providers/[id]` | Update (admin only) |
| DELETE | `/api/admin/providers/[id]` | Delete (admin only) |
| POST   | `/api/admin/providers/[id]/toggle` | Enable/disable (admin only) |
| POST   | `/api/admin/providers/[id]/preview` | Run preview |
| POST   | `/api/admin/providers/[id]/run` | Enqueue jobs |

`source_type` is locked to `'json'` in this milestone (server-side rejection otherwise).
