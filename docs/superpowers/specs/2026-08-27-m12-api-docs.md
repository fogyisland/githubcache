# M12 — API v2 Docs Site — Design

**Date:** 2026-08-27
**Status:** Draft (awaiting user review)
**Tag target:** `m12-api-docs`
**Resumes from:** M11 SHIPPED (`m11-detailed-surfaces` at `30ff2e7`) + M11.16 deadlock fix (`83ea4cd`)

## Goal

Ship a public, themed, server-rendered API documentation site at `/docs/*` that:

1. Documents every **public** endpoint (`POST /api/query`, `GET /api/v1/status`, and the new `GET /api/v1/repos/{owner}/{name}`).
2. Is generated from a single source of truth — Zod schemas — so docs never drift from code.
3. Carries the terminal / editorial / brutalist theme system from M10 through to docs pages.
4. Closes the existing gap where `/api/v1/repos/{owner}/{name}` is referenced by `src/app/repo/[owner]/[name]/_components/api-shape.tsx:18` but does not actually exist as a route.

## Non-goals (out of scope for M12)

- Documenting admin endpoints (`/api/admin/*`) — admin users have a different audit story.
- Interactive "Try it" with in-browser execution.
- Auto-generated SDKs.
- OpenAPI export — a future milestone can add it on top of the Zod registry.
- New design tokens. Reuses existing `--font-mono`, `--color-*` etc.

## Architecture

Three layers:

```
┌─────────────────────────────────────────┐
│  Zod schemas (src/lib/api-docs/schemas) │   ← source of truth
│  per endpoint: request / response /     │
│  headers / errors                       │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  Registry (src/lib/api-docs/registry.ts)│   ← ordered array of
│  ENDPOINT_DOCS: EndpointDoc[]           │     EndpointDoc
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  Renderer (src/app/docs/_components)    │   ← server components,
│  DocsShell, DocsSidebar, EndpointPage,  │     theme-aware
│  SchemaViewer, CurlExample, ...         │
└─────────────────────────────────────────┘
```

### EndpointDoc type

```typescript
// src/lib/api-docs/types.ts
export interface EndpointDoc {
  /** stable slug used in /docs/[slug], e.g. "api/v1-status" */
  slug: string;
  /** full path with placeholders, e.g. "/api/v1/repos/{owner}/{name}" */
  path: string;
  method: 'GET' | 'POST';
  /** one-line summary shown in sidebar + page header */
  summary: string;
  /** longer description (markdown-rendered via simple regex helpers, no library) */
  description: string;
  /** whether auth is required; if true, "X-API-Key" badge appears */
  auth: 'none' | 'X-API-Key';
  /** rate-limit summary, e.g. "60 req/min per API key (durable)" */
  rateLimit: string;
  /** path params, query params, and body schema (Zod) — combined */
  request?: ParamDoc[];
  /** success response body — Zod schema, used by SchemaViewer + sample */
  response: z.ZodTypeAny;
  /** named response samples for the JSON example block */
  responseSamples: Record<string, unknown>;
  /** response headers worth documenting */
  headers?: HeaderDoc[];
  /** error responses (status code → when it happens + body shape) */
  errors: ErrorDoc[];
}

export interface ParamDoc {
  name: string;
  in: 'path' | 'query' | 'header' | 'body';
  type: string;
  required: boolean;
  description: string;
}

export interface HeaderDoc {
  name: string;
  description: string;
  example: string;
}

export interface ErrorDoc {
  status: number;
  error: string;       // the `error` field value in the body
  when: string;        // human-readable condition
}
```

### Zod schemas reuse existing types

The existing Zod schemas live where their domain logic lives. Docs imports them, not redefine them:

| Endpoint | Existing Zod schema |
|---|---|
| `POST /api/query` | `src/lib/cache/parser.ts: parseNodes` |
| `GET /api/v1/status` | new — extract from `src/app/api/v1/status/route.ts` |
| `GET /api/v1/repos/{owner}/{name}` | `src/lib/cache/lookup.ts: QueryResult` (re-export `z.union([ResultOk, ResultNotFound, ResultError])`) |

If a route's response is currently plain TS types, extract a Zod schema first (small refactor). Schemas live next to their route or module; the registry imports them.

### SchemaViewer

Recursive component that walks a Zod schema and renders:

- `ZodObject` → table of properties with row per field (name | type | required | description)
- `ZodString`, `ZodNumber`, `ZodBoolean`, `ZodEnum`, `ZodLiteral` → inline type chip
- `ZodArray(inner)` → table of inner with "(array)" indicator
- `ZodUnion([a, b])` → side-by-side "or" columns
- `ZodOptional(inner)` → inner + "(optional)" badge
- `ZodNullable(inner)` → inner + "(nullable)" badge
- `ZodDate` → "string (ISO 8601)"
- Unknown → falls back to "any" + a comment

Descriptions come from `.describe('...')` calls on the schema. If a schema lacks descriptions, add them.

## Endpoints to document (3)

### 1. `GET /api/v1/status`

- Auth: none
- Rate limit: none (already-public, low-cost)
- Reuses the existing route handler at `src/app/api/v1/status/route.ts`
- Schema extract: refactor route handler to use a new `src/lib/api-docs/schemas/v1-status.ts`

### 2. `GET /api/v1/repos/{owner}/{name}`  (NEW in M12.1)

- Auth: none
- Rate limit: per-IP via M9.2 bucket (`PUBLIC_LOOKUP_RATE_PER_MIN`)
- 200 → `{ repository: RepoMetadata, fetch_status: 'ok' | 'not_found' | 'error', fetched_at, stale? }`
- 404 → repo not in cache and not on GitHub
- 429 → per-IP rate limit
- 503 → no GitHub tokens configured

Implementation: new route at `src/app/api/v1/repos/[owner]/[name]/route.ts`. Delegates to `lookupRepo(owner, name)` from M9.3. Wraps result in `NextResponse.json` with appropriate status code.

### 3. `POST /api/query`

- Auth: `X-API-Key` (M3)
- Rate limit: per-key durable bucket (M8.1 / M11.16)
- Body: `{ nodes: [{ owner, name }] }` — validated via `parseNodes`
- Response: `{ results: QueryResult[], summary: { hit, miss, stale } }`
- Errors: 400 (malformed body), 401 (missing key), 403 (invalid key), 429 (rate limit)

## Pages and routing

```
/docs                                 ← landing
/docs/api/v1-status                   ← /api/v1/status
/docs/api/v1-repos                    ← /api/v1/repos/{owner}/{name}
/docs/api/query                       ← POST /api/query
```

Each endpoint page is a server component that:
1. Looks up its `EndpointDoc` from `ENDPOINT_DOCS` by slug
2. Renders `<EndpointPage doc={doc} />`
3. Renders a "Try it" block with a copy-able curl example

## Testing strategy

- **Unit tests**: registry completeness (every public route has an EndpointDoc), Zod walker correctness (snapshot a few outputs), endpoint-page rendering via `renderToStaticMarkup`.
- **Integration tests**:
  - `api-v1-repos-route.test.ts`: hit the new endpoint with known repos (octocat/Hello-World, microsoft/typescript, a not-found case). Verify status + body shape.
  - `api-docs-routes.test.ts`: render `/docs`, `/docs/api/query`, `/docs/api/v1-repos`, `/docs/api/v1-status` via Next.js test setup; assert they don't throw and contain expected method/path markers.
- **Type safety**: Zod schemas are the source of truth, so component prop types flow from them. If a route's response schema changes, the registry + SchemaViewer types break — caught at typecheck.
- **CSS verification**: curl `/docs/api/query` with `data-theme=terminal|editorial|brutalist` cookie, dump HTML, verify the expected selectors + colors appear. Same probe pattern used in M10 verification.

## Risks

1. **`POST /api/query` response uses `Promise.all` over arbitrary node lists** — sample responses may grow unbounded. Limit `responseSamples` to 1-node batch.
2. **Zod union rendering in SchemaViewer** — `QueryResult = ResultOk | ResultNotFound | ResultError` is a union with three complex members. The walker must render all three branches side-by-side or as tabs. Plan: side-by-side columns with role labels.
3. **Per-IP rate limit on the new `GET /api/v1/repos/...`** — same M11.16 fix applies. The `incrementIpBucket` is already M11.16-safe.
4. **Tag count grows** — this is the 13th tag. Memory file `project_milestone_tags.md` should be updated as part of M12.10.

## Migration / env / breaking changes

- No new env vars.
- No DB migration. The new route uses existing tables.
- **Breaking**: `/api/v1/repos/{owner}/{name}` is a NEW public route. It is purely additive; no existing endpoint changes shape. `api-shape.tsx` link text changes from "this is what the v1 API would return" to a real GET-able URL.

## Out of scope (deferred)

- Versioned docs (`/docs/v1`, `/docs/v2`).
- Auto-generated TypeScript SDK from Zod schemas.
